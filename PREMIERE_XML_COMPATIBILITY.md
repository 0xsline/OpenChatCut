# Premiere legacy FCP7 XML compatibility notes

This note distinguishes documented XMEML structure from behavior Adobe says Premiere imports and from behavior that still needs a real Premiere test. “FCP7 XML” here means legacy `xmeml`/FCP XML (`.xml`), not Apple FCPXML (`.fcpxml`). Adobe documents that Premiere imports FCP7 `.xml` directly; current Adobe documentation separately says `.fcpxml` from Final Cut Pro X is not directly importable. The existing FCPXML export remains a separate format and code path. [Adobe FCP7 migration guide](https://helpx.adobe.com/ro/premiere-pro/how-to/migrate-from-final-cut-pro.html) · [Adobe FCPX import guide](https://helpx.adobe.com/premiere/desktop/organize-media/import-files/migrate-from-final-cut-pro-x.html)

## Evidence levels

- **Documented XMEML** means the structure is in Apple's archived Final Cut Pro 7 XML specification and examples. Apple calls it a retired document, so it describes the interchange format, not a current Premiere importer guarantee. [Apple FCP7 XML overview](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/)
- **Adobe import behavior** means Adobe documentation explicitly describes Premiere's FCP XML import/conversion behavior. Most detailed mapping tables are in the archived 2015 Premiere guide; the current Adobe guide confirms the XMEML exchange route and warns that effects/features may not transfer exactly.
- **Unverified** means no published Adobe importer details or local Premiere import test were found. A schema-valid XML file alone is not evidence that Premiere imports the feature correctly. Apple's own DTD page cautions that even DTD-valid XML can fail during import. [Apple XMEML DTD](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/DTD/DTD.html)

No Premiere application import has been performed for this project. Do not describe this serializer as Premiere-verified until a real application import has been run and inspected.

## Compatibility matrix

| Area | Documented structure / Adobe import claim | Recommended initial behavior | Evidence / remaining uncertainty |
|---|---|---|---|
| Sequence, frame rate, dimensions | `<xmeml version="5"><sequence>...<rate><timebase>30</timebase><ntsc>TRUE</ntsc></rate>...<media><video><format><samplecharacteristics><width>1920</width><height>1080</height><rate>…</rate></samplecharacteristics></format><track>…</track></video><audio>…</audio></media></sequence></xmeml>`. Apple's sequence example defines format/output fields as sequence settings. `timebase=30, ntsc=TRUE` represents 29.97; use the exact supported pair from Apple's frame-rate table. | Emit project/sequence rate and canvas dimensions from timeline state; don't infer them from a source file. | Apple sequence examples and frame-rate table; Adobe says sequence settings are retained on import. Exact current Premiere interpretation of every format field is not independently tested. [Apple encoding](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Basics/Basics.html) · [Apple frame-rate table](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/FrameRate/FrameRate.html) · [Adobe archived guide](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Video/audio tracks | Repeated `<video><track>…</track></video>` and `<audio><track>…</track></audio>` hold ordered `clipitem`s; track children may also be `transitionitem` or `generatoritem`. Separate `<sourcetrack><mediatype>video|audio</mediatype><trackindex>…</trackindex></sourcetrack>` selects source stream. | Keep independent media tracks and preserve timeline lane ordering; create only required tracks. | DTD and sequence examples establish structure; Adobe says it retains track layout. [Apple DTD](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/DTD/DTD.html) · [Adobe archived guide](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Files and paths | A media reference is `<file id="f1"><name>shot.mov</name><pathurl>file://localhost/C:/media/shot.mov</pathurl><rate>…source rate…</rate><duration>…source frames…</duration><timecode>…</timecode></file>`; later uses can refer to `<file id="f1"/>`. Apple explicitly percent-escapes URL characters such as spaces. | Keep original media references. Serialize a path only from an actual resolved/managed file location; do not invent a `file://` URL for a server-relative or unresolved source. If no real resolved path exists, surface an offline/relink warning or fail according to product policy. | Documented schema/example; no guarantee every host path is portable. [Apple file example](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Basics/Basics.html) |
| Clip source trim vs timeline placement | `<clipitem><duration>…</duration><rate>…</rate><in>source-frame</in><out>source-edge</out><start>sequence-frame</start><end>sequence-edge</end><file id="f1"/></clipitem>`. `in/out` refer to media; `start/end` place the item in its parent sequence. Apple uses 0-based first-frame numbering for `in/start`, but a distinct 1-based ordinal convention for `out/end`; transitions can require extended handles and `-1` computed endpoints. | Preserve source trims and timeline placement in their respective clocks. Keep the `out/end` ordinal conversion centralized and explicit. | Apple explains the two timing domains and endpoint convention; Premiere's exact edge import behavior still needs application validation. [Apple timing notes](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Topics/Topics.html) |
| Mixed sequence/source frame rates | `<sequence><rate>…timeline rate…</rate>` and `<clipitem><rate>…timeline rate…</rate>` describe timeline timing; `<file><rate>…native media rate…</rate></file>` describes the media clock. The `in/out` frame values are source-media frames while `start/end` are sequence frames. | Use the measured rational source FPS for each file and project FPS for sequence and clipitem timing. Convert project-rate frame counts into each source clock for `in/out`; copying project frame numbers into source fields is wrong when rates differ. Source timecode is not FPS metadata. If native FPS is unknown, stop with a clear issue. | Apple documents separate timing clocks. The serializer declares measured source rates and explicitly converts source trims, so correctness does not rely on Premiere conforming a mismatched or guessed file rate. Automatic conform behavior for mismatched XML metadata is not specified. Source-rate probing is a product requirement, not an Adobe behavior claim. [Apple timing notes](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Topics/Topics.html) · [Apple frame-rate table](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/FrameRate/FrameRate.html) |
| Source and sequence timecode, DF/NDF | `<timecode><rate>…</rate><string>01:00:00;00</string><frame>…</frame><source>source</source><displayformat>DF</displayformat><reel><name>…</name></reel></timecode>`. DTD permits `string`, `frame`, `source`, `displayformat`, and `reel`. | Keep source timecode separate from file FPS. Preserve sequence starting TC (Adobe explicitly says it retains sequence start TC); emit `displayformat` only with the best known DF/NDF value. | Adobe confirms sequence start TC. Apple's element schema/sample supports `displayformat`, but Apple's Topics section also says drop/non-drop character is not included in an XML export, which conflicts with that field/sample; DF/NDF round-trip should be treated as uncertain until Premiere is tested. [Apple timecode example](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Basics/Basics.html) · [Apple topics](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Topics/Topics.html) · [Adobe archived guide](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Linked A/V | A clip can reference one file with distinct source tracks. Apple's explicit link example uses `<link><mediatype>audio</mediatype><trackindex>1</trackindex><clipindex>1</clipindex><groupindex>1</groupindex></link>` (plus corresponding video link); alternate linkage uses `<linkclipref>clip-id</linkclipref>`. | Link split audio/video items when they represent the same source clip and preserve original audio if video is baked. Avoid linking separate timeline items just because their media happens to match. | Apple demonstrates both forms. Premiere editable-link import has not been tested locally. [Apple linking example](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Basics/Basics.html) |
| Constant speed, reverse, freeze, variable speed | Apple documents a generic Time Remap representation: `<filter><effect><parameter><parameterid>graphdict</parameterid><keyframe><when>timeline-frame</when><value>source-frame</value><speedvirtualkf>TRUE</speedvirtualkf>…</keyframe>…</parameter></effect></filter>`. The `when` coordinate follows the clip's adjusted timeline clock, while graph values point into the physical source-frame clock. Linear `when`→`value` points describe constant speed in FCP; nonlinear values describe variable speed. Version 5 additionally permits `anchoroffset`. | Keep positive constant speed editable with native graphdict timing only when the trimmed source window converts from project frames to measured media frames, then maps into the adjusted clip clock without losing endpoints. Bake or block retimes whose source-frame direction, virtual edges, or endpoints cannot be represented exactly. | Apple documents structure and FCP interpretation, including its last-frame adjustment and constant-reverse `+1` adjustment; Adobe broadly says speed variations migrate from FCP7, but does not publish the exact Premiere parameter/effect IDs or speed ratio convention. Current checks cover XML structure and frame-clock math only; no Premiere import has been run. [Apple speed notes](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Topics/Topics.html) · [Apple time-remap element](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Elements/Elements.html) · [Adobe migration guide](https://helpx.adobe.com/ro/premiere-pro/how-to/migrate-from-final-cut-pro.html) |
| Motion transforms and keyframes | Generic motion filters use `<effect><name>Basic Motion</name><effectid>basic</effectid><effectcategory>motion</effectcategory><effecttype>motion</effecttype><mediatype>video</mediatype><parameter><parameterid>scale</parameterid><name>Scale</name><value>…</value></parameter><parameter><parameterid>center</parameterid><name>Center</name><value><horiz>…</horiz><vert>…</vert></value></parameter></effect>`. Keyframes use `<keyframe><when>…</when><value>…</value><interpolation><name>FCPCurve</name></interpolation>…</keyframe>`. | For known source dimensions, emit centered uniform Basic Motion scale matching the timeline's `contain` or `cover` fit. Unknown source dimensions produce a visible warning and retain Premiere's default scale. Square-pixel assumptions and scale rounding within one output pixel are best-effort. Rotation, position offsets, opacity changes, fades, crop, rounded corners, dynamic effects, and visual keyframes are baked when an isolated render preserves semantics. XMEML track visibility can use `<enabled>FALSE</enabled>`; audio mute can use an audio companion clip with `<enabled>FALSE</enabled>` while keeping its linked video. | Apple has a real `basicmotion` sample and keyframe grammar; Adobe says basic motion and opacity plus keyframes are retained from FCP XML, but matching OpenChatCut values/interpolation exactly is untested. Basic Motion auto-fit and the stated pixel tolerances are implementation decisions, not guarantees from those sources. [Apple motion example](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Applications/Applications.html) · [Apple keyframe catalog](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Elements/Elements.html) · [Adobe archived guide](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Opacity | XMEML encodes effect parameters and keyframes generically; a representative effect is a `<filter>` containing `<effect>` and a parameter with static `<value>` or animated `<keyframe>` values. Apple's effect examples show an effect parameter may hold either value or keyframes, not both. | Keep only simple constant opacity or a known, tested keyframe mapping editable; render complex opacity/compositing combinations when a safe isolated render exists. | Adobe says FCP opacity and opacity keyframes are retained; Apple's generic schema alone does not specify a universal Premiere parameter ID. [Apple effect example](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Basics/Basics.html) · [Adobe archived guide](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Audio volume/fades | Premiere-authored XML examples use `<effectid>audiolevels</effectid><effectcategory>audiolevels</effectcategory><effecttype>audiolevels</effecttype><mediatype>audio</mediatype>` with `<parameter authoringApp="PremierePro"><parameterid>level</parameterid><name>Level</name><value>linear-gain</value></parameter>` and `<pproBypass>false</pproBypass>`. Apple defines Level as linear amplitude (`gain = 10^(dB/20)`). Animated parameters use ordered keyframes. | Keep static volume and simple linear fades/keyframes editable when they fit the same `Level` parameter model; bake nonlinear/eased volume curves or combinations the serializer cannot represent safely. Keep original audio attached to a visual bake. | Apple documents gain math. Adobe's official FCPX-import table says audio volume/keyframes and fade handles are recreated as audio-level keyframes, but that is FCPXML-import evidence, not the FCP7 importer. Blender Studio reports a Premiere-authored FCP7 audio-level block and successful XML re-import with levels carried; this is an authoritative production example, not an Adobe specification. Adobe's current FCP XML export documentation separately cautions pan/gain/level may not transfer accurately. [Apple audio levels](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Topics/Topics.html) · [Blender Studio's Premiere XML pipeline](https://www.blenderstudio.cn/en/blog/opentimelineio-in-blender/) · [Adobe FCPX supported elements](https://helpx.adobe.com/premiere/desktop/organize-media/transfer-files/supported-elements-for-final-cut-pro-x.html) · [Adobe current transfer caveat](https://helpx.adobe.com/premiere/desktop/render-and-export/export-files/export-a-project-as-a-final-cut-pro-xml-file.html) |
| Transitions and overlaps | `<transitionitem><rate>…</rate><start>…</start><end>…</end><alignment>center</alignment><effect><name>Cross Dissolve</name>…</effect></transitionitem>`. Adjacent clip handles may extend before/after the edit; Apple uses `-1` for a computed endpoint in its cross-dissolve example. | A transition depends on both adjacent clips and available source handles. The selective per-item baker cannot recreate that overlap as independent clips; block with an issue until a multi-clip/group render or verified native mapping exists. | Apple gives a concrete XMEML transition sample and explains handle changes. Adobe maps FCP7 transitions to supported Premiere effects with some lossy substitutions, but our timeline overlap model has not been verified in Premiere. [Apple transition example](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Basics/Basics.html) · [Adobe mapping tables](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Markers | `<marker><name>…</name><in>…</in><out>…</out><comment>…</comment></marker>` can be nested where permitted, including sequence/clip items. | Preserve sequence markers. Warn if clip markers/colors or marker-specific frame-rate conversion cannot be represented confidently. | Adobe explicitly says sequence markers are retained. Per-clip marker behavior wasn't confirmed from Adobe documentation. [Apple DTD](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/DTD/DTD.html) · [Adobe archived guide](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Captions and titles | XMEML v5's DTD has no dedicated native caption-track element. It does allow `<generatoritem>` with an effect; Apple's subtitle sample creates `generatoritem` clips using a `Text` generator and a `str` parameter. Adobe says text from FCP Text generators imports as Premiere titles. | Enabled timeline captions are a global overlay and cannot be preserved by isolated clip bakes. Block with an issue and point users to the separate SRT/TXT export until a timeline-composite render exists. Do not call Text generators native caption tracks. | Caption-via-title is an inference from Apple's generator example and Adobe's Text-generator import statement; native caption import is not established. [Apple subtitle example](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/Applications/Applications.html) · [Adobe archived guide](https://helpx.adobe.com/archive/en/premiere-pro/cc/2015/premiere_pro_reference.pdf) |
| Nesting | The XMEML DTD permits a `<sequence>` inside a `<clipitem>` and sequence references, so nested timelines are expressible. | A nested sequence needs its referenced timeline graph or a group render; if neither is available, block with a visible nesting issue. | Apple schema proves representation only. No Adobe source confirming legacy import semantics for our generated nesting was found. [Apple XMEML DTD](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/FinalCutPro_XML/DTD/DTD.html) |

## Small illustrative skeleton

This fragment demonstrates the documented XMEML field separation and real media path shape. It is not a Premiere-generated sample and is not a claim of import verification. Frame values are illustrative; real `in/out` must be converted to the source file's measured frame rate, while `start/end` use sequence frames.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE xmeml>
<xmeml version="5">
  <sequence id="sequence-1">
    <name>OpenChatCut Edit</name>
    <duration>240</duration>
    <rate><timebase>24</timebase><ntsc>FALSE</ntsc></rate>
    <timecode>
      <rate><timebase>24</timebase><ntsc>FALSE</ntsc></rate>
      <string>01:00:00:00</string><frame>86400</frame>
      <source>source</source><displayformat>NDF</displayformat>
    </timecode>
    <media>
      <video>
        <format><samplecharacteristics>
          <width>1920</width><height>1080</height>
          <rate><timebase>24</timebase><ntsc>FALSE</ntsc></rate>
        </samplecharacteristics></format>
        <track><clipitem id="v1">
          <name>shot.mov</name><duration>48</duration>
          <rate><timebase>24</timebase><ntsc>FALSE</ntsc></rate>
          <in>120</in><out>180</out><start>0</start><end>48</end>
          <file id="f1"><name>shot.mov</name>
            <pathurl>file://localhost/C:/media/shot.mov</pathurl>
            <rate><timebase>30</timebase><ntsc>FALSE</ntsc></rate>
            <duration>900</duration>
          </file>
          <sourcetrack><mediatype>video</mediatype><trackindex>1</trackindex></sourcetrack>
          <link><linkclipref>v1</linkclipref></link>
          <link><linkclipref>a1</linkclipref><groupindex>1</groupindex></link>
        </clipitem></track>
      </video>
      <audio><format/><outputs/><track><clipitem id="a1">
        <name>shot.mov</name><duration>48</duration>
        <rate><timebase>24</timebase><ntsc>FALSE</ntsc></rate>
        <in>120</in><out>180</out><start>0</start><end>48</end>
        <file id="f1"/>
        <sourcetrack><mediatype>audio</mediatype><trackindex>1</trackindex></sourcetrack>
      </clipitem></track></audio>
    </media>
    <marker><name>Review</name><in>120</in><out>121</out><comment>Check this cut</comment></marker>
  </sequence>
</xmeml>
```

### Practical support policy

Prioritize direct, editable cuts that reference original files with export-time-resolved local paths and measured native frame rates. Convert source trims using their measured rate rather than guessed metadata or presumed automatic conform behavior. Bake only unsupported per-item effects when the render preserves timing and original audio; references must name actual exported/managed files. Treat a failed required bake as an export failure rather than emitting a placeholder. If a feature depends on global compositing or neighboring clips (captions, watermark, transitions, nesting), stop with a visible issue until a correct layer/group render or verified native mapping exists. Keep `.fcpxml` on its current FCPXML serializer and behavior; the legacy Premiere `.xml` route is a separate format.
